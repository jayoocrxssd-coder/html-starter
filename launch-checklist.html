Upgrade to Production Auth
UP NEXT
  • Replace localStorage account store with a real auth provider recommended
    Accounts currently live only in the visitor's browser — they vanish on private mode or a new device. Replace handleAuth() in index.html with a provider call. Best options: Supabase Auth (free, Postgres-backed), Clerk (drop-in UI), or extend the Firebase Auth already imported in app.html.
  • Store a real JWT, not a static '1' flag
    After sign-in, store the provider's JWT. The app gate should decode and validate the token (check expiry, signature). Add expiry checks so stale sessions auto-redirect to /.
  • Wire Google Sign-In to a real OAuth flow
    Both the landing page handleGoogleSignIn() and the app's Google button simulate the flow. Connect them to your chosen provider's Google OAuth — Supabase and Clerk handle this with no extra code on your end.
  • Add "Forgot password?" link to the auth card
    The auth overlay in index.html has no password reset option. Add a link below the password field that triggers the provider's reset email. Required — users will need this from day one.

4
Firebase Config & Security Rules
REVIEW
  • Verify Firestore Security Rules lock down user data security
    Firebase config (projectId: "createwarrom") is in app.html. The Web API key is fine to be public, but Firestore rules must restrict reads/writes to the authenticated user. Go to Firebase Console → Firestore → Rules and verify — default rules allow public access.
  • Add your production domain to Firebase Auth authorized domains
    Firebase Auth only allows sign-in from listed domains. Go to Firebase Console → Authentication → Settings → Authorized domains. Add your custom domain and yourapp.netlify.app before going live.
  • Remove unused Firebase service imports
    app.html imports Firebase Analytics, Auth, Firestore, and Drive. Remove imports for any services not actively used to reduce bundle weight and attack surface.

LATER

AXIS AI (Anthropic)
LATER
  • Move Anthropic key to a server-side proxy security
    Users currently paste their own key into Settings — it's stored in localStorage and sent directly from the browser. For a hosted product, proxy calls through POST /api/axis (a Netlify Function) with your key as an env var. Protects the key and enables rate limiting.
  • Inject user context into the AXIS system prompt
    AXIS answers generic questions well but doesn't know the user's actual P&L, missions, or calendar. Pass a summary of stratusWR_v31 as a system prompt prefix so AXIS can answer "What's my profit this month?" with real data.
  • Add per-user rate limiting on the AXIS proxy
    Without rate limiting a single user can burn your API budget. Track calls per user JWT in Redis/Upstash (free tier: 10k req/day) and return 429 when the limit is hit.
