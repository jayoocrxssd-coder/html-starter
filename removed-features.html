AXIS Standalone Page
AI Command Interface · Dedicated nav page
Removed
What it did

AXIS had its own dedicated full-page view accessible from the sidebar under a "AXIS" nav item. This page mirrored the AXIS chat panel already embedded on the Dashboard — it displayed the same conversation history, offered the same Briefing button, and showed an AI status indicator. It was essentially a full-screen version of the Dashboard's AI panel.

Why removed

The AXIS panel embedded on the Dashboard (and the floating overlay accessible via the ⤢ expand button) fully covers this use case. Having a third entry point — the standalone nav page — created redundancy in the nav and confusion about which "AXIS" was canonical. The Dashboard panel is the primary home for AXIS; the overlay is the immersive mode. The standalone page added nothing unique.

What was deleted
  • NAV Sidebar nav item: id="nav-axis" (onclick="showPage('axis')")
  • NAV Mobile "more" sheet entry: Axis item in .mob-more-sheet
  • HTML Full standalone page: id="page-axis" — entire div block including AXIS page header, no-key banner, chat message container, and input textarea
  • JS renderAxisPage() — synced overlay messages to the standalone page on navigation
  • JS resetAxisChat() — delegated to resetAIChat() and synced standalone panel
  • JS sendAxisChat() — routed input to overlay and synced results back
  • JS runBriefingAxis() — triggered briefing from standalone page context
  • JS Removed 'axis' from the _morePages array in showPage()
  • JS Removed if(page==='axis'){renderAxisPage();} dispatch from showPage()
What was kept

The AXIS panel embedded on the Dashboard page is fully intact. The floating AXIS overlay (accessible via the ⤢ expand button on the Dashboard) is fully intact. All AI logic, API key handling, briefing generation, and chat functionality is unchanged.

Tax Tracker
Estimated quarterly taxes · Deductible categories
Removed
What it did

The Tax Tracker was a secondary tab within the Bills & Expenses page. It displayed estimated quarterly tax payments based on a 25% effective rate, a grid of deductible expense categories (with amounts auto-pulled from P&L data), a year-over-year summary chart, and a filing checklist. It supported both Business and Personal modes and let users select the tax year. All figures were estimates — the feature explicitly noted users should consult a tax professional.

Why removed

The Tax Tracker was built on rough estimations (fixed 25% rate) rather than real tax logic, making its figures unreliable for actual financial decisions. It added complexity to the Bills page UI without delivering actionable data. Beta streamlining prioritizes the P&L Tracker and Invoices for financial tracking — tax estimation is out of scope for this release.

What was deleted
  • TAB Bills page tab bar button: id="bmtab-tax" (onclick="setBillsMainTab('tax')")
  • TAB Entire Bills page tab bar (.bills-main-tab-bar) removed since only one tab remained
  • HTML id="taxSection" div — entire Tax Tracker HTML block including: quarterly payment strip, KPI grid, deductible categories list, year summary chart, filing checklist
  • JS renderTaxTracker() — main render function populating all tax UI
  • JS setBillsMainTab(tab) — tab switcher between Bills and Tax sections
  • JS setTaxMode(mode) — toggled between Business and Personal tax modes
  • JS Variable _taxMode declaration
  • CSS .tax-kpi-grid, .tax-q-strip, .tax-q-card, .tax-q-card.active-q, .tax-q-card.paid-q, .tax-q-card-accent, .tax-q-label, .tax-q-amount, .tax-q-due

Video Meet
WAR ROOM · MEET · In-app video conferencing UI
Removed
What it did

Video Meet was a full-screen video conferencing overlay (id="vcallOverlay") accessible via a "MEET" chip in the topbar. It included a lobby screen where users could preview their camera and start/join a meeting with a randomly generated room code. The in-call view showed a participant grid, picture-in-picture, a timer, mute/camera/screen share controls, an in-call chat panel, and a participant list. Meeting history was stored in S.vcMeetings. Note: the feature simulated video (no actual WebRTC peer connections were established) — it was a UI prototype.

Why removed

Video Meet was a simulated prototype — it had no real WebRTC infrastructure, meaning no actual video calls could occur between users. Including a non-functional video conferencing feature in a beta release is misleading. The substantial CSS (~90 lines) and JS (~480 lines) was dead weight. Users expecting real video calls would be confused or disappointed.

What was deleted
  • CHIP Topbar "MEET" button: id="meetChip" (onclick="openVCallLobby()") and its preceding separator
  • HTML Entire video call overlay: id="vcallOverlay" — all lobby, participant grid, controls, chat panel, screen picker, and share bar HTML (~246 lines)
  • JS openVCallLobby(), joinVCall(), endVCall()
  • JS renderVCallHistory(), renderVCallParticipants(), _renderVCallParticipantList()
  • JS setVCallTab(), updateVCallControls(), toggleVCallControl()
  • JS toggleVCallChat(), toggleVCallParticipants(), toggleVCallParticipantsList()
  • JS sendVCallChat()
  • JS State object _vcState and all associated timer/stream management code
  • CSS Full .vcall-* CSS block (~92 lines): .vcall-overlay, .vcall-topbar, .vcall-logo, .vcall-grid, .vcall-tile, .vcall-controls, .vcall-btn, .vcall-lobby, .vcall-chat-panel, screen picker styles, share bar styles, lobby styles, etc.
  • CSS Responsive: vcall mobile safe-area overrides, .vcall-chat-panel { display:none } portrait fix, mobile tap-target enlargements, lobby camera size override
  • JS Removed meetChip insertion-before logic from FUN mode button initializer

Update Manager
Safe updates · Data merging · Backup history · Data patcher
Removed
What it did

The Update Manager was a dedicated page (id="page-update") with a 3-step workflow for upgrading the War Room HTML file without losing user data. Step 1: export a backup. Step 2: load a new .html update file. Step 3: preview the merge and apply. It also included a "Data Patcher" collapsible panel with 6 database maintenance patches (fix duplicate IDs, remove orphaned tasks/events/entries/streams, recalibrate ID counter) runnable on demand. A backup history list tracked past exports with timestamps and record counts.

Why removed

The Update Manager addressed a very specific distribution model where the entire app is a single HTML file passed around and upgraded manually. In a hosted/deployed context, app updates are pushed server-side — no merge workflow is needed. The data patcher utilities, while useful for data hygiene, are advanced developer tools not appropriate for general beta users. The feature added a full page of complex UI and ~430 lines of JS for an edge-case workflow.

What was deleted
  • NAV Sidebar nav item: id="nav-update" (onclick="showPage('update')")
  • HTML Full Update Manager page: id="page-update" — 3-step card flow, status strip, data summary list, backup history list, data patcher collapsible panel with patch list and log
  • HTML Profile & Settings: "Update Manager" card (blue-bordered call-to-action with load-update file input)
  • JS loadUpdateFile() — reads a War Room HTML update file
  • JS showUpdatePreview() — populates step 3 preview with record counts and version diff
  • JS _applyUpdateExec(), applyUpdate() — executes the data-preserving merge
  • JS cancelUpdate() — resets the update flow UI
  • JS exportAndMarkStep1() — export + unlock step 2 flow
  • JS renderUpdatePage(), renderUpdateStatusStrip(), renderDataSummary(), renderBackupHistory()
  • JS renderPatchList(), selectPatch(), runSelectedPatch(), patchLog(), clearPatchLog(), setPatcherStatus(), togglePatcher()
  • JS Data patcher functions: patchFixDuplicateIds(), patchOrphanedTasks(), patchOrphanedEvents(), patchOrphanedEntries(), patchOrphanedStreams(), patchRecalibrateNextId(), patchRunAll()
  • JS PATCHES array, selectedPatchId, step1Done, pendingUpdateHTML variable declarations
  • JS Command palette entry: "Update Manager" navigate action
  • JS Removed if(page==='update'){renderUpdatePage();} dispatch from showPage()
  • CSS .backup-card, .backup-card-header, .backup-card-body, .backup-history-row, .backup-icon
  • CSS .update-status, .update-dot, .update-dot.green, .update-dot.amber, .update-dot.red
  • CSS .update-preview-row, .update-preview-icon variants
  • CSS .diff-added, .diff-removed, .diff-unchanged
  • CSS Responsive: #page-update .row { flex-direction: column } mobile stack
What was kept

The standard "Restore from Backup" functionality in Profile & Settings (import JSON backup) is fully intact. The exportAllData() function and auto-backup-on-save logic remain. Backup history is still tracked in S.backups and exported with data. Only the dedicated Update Manager UI and data patcher were removed.
