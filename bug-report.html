app.html · line ~6092

app.html · lines 1576, 9133, 9149
The <script type="module"> block set window._fbDb = getFirestore(app) using the MODULAR Firebase SDK. handlePendingJoin() then called window._fbDb.collection() which doesn't exist in the modular SDK — instant crash.

✓ Hoisted _cloudSynced to module scope. signOut() now resets it to false so the next sign-in re-pulls cloud data correctly.

Broken Firebase Google credential in app
app.html · line ~9417
GoogleAuthProvider.credential(null, access_token) — The GSI OAuth2 token client returns only an access token, not an id_token. Firebase Auth requires id_token as the first argument. Fixed

app.html · saveToCloud + loadFromCloud
If Firebase Firestore failed to initialise (network offline, SDK load error), _fbDb would be null but saveToCloud() and loadFromCloud() only checked if(!_fbDb) at the top. If the Firestore object existed but had no collection method (wrong SDK instance), the call would still throw.
✓ Guards now check !_fbDb || !_fbDb.collection before proceeding, making both functions safe against any partial-init state.

Critical

Firebase Console → Authentication → Sign-in method
Until you enable the Email/Password provider in your Firebase project, createUserWithEmailAndPassword() and signInWithEmailAndPassword() will throw auth/operation-not-allowed. No email account can be created or used.
⚙ Firebase Console → Authentication → Sign-in method → Enable Email/Password
Critical
Firestore database not created / security rules missing
Firebase Console → Firestore Database
Cloud sync writes to war_room_data/{uid} in Firestore. If the database doesn't exist, all saves silently fail. Without security rules, data is either unreadable or fully public.
⚙ Create the Firestore database (production mode), then set this rule:

match /war_room_data/{userId} {
  allow read, write: if request.auth != null
  && request.auth.uid == userId;
}
